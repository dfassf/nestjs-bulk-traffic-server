# nestjs-bulk-traffic-server 회고

대용량 트래픽 흡수용 NestJS 골격 서버. 우선순위 큐 + Worker Thread + Circuit Breaker + 큐 영속화.
이후 Go Heavy Worker Engine 추가로 듀얼 엔진 (NestJS + Go).

비즈니스 API 없는 인프라 골격. 부하 테스트 대시보드(SSE 스트리밍) 포함.

---

## 큰 의사결정

### 모든 요청 큐 미들웨어 통과 (health/queue-stats 제외)
- **결정**: `QueueMiddleware`가 method+path+body 분석 → priority/category/size/workloadType 자동 계산
- **이유**: 요청 즉시 실행 X. 큐 적재 후 백프레셔 + 우선순위 정렬
- **트레이드오프**: P50 latency ↑ (큐 통과 비용), P99 안정성 ↑↑

### 우선순위 큐 3단계 (high/normal/low)
- `priority >= 5` → high
- `priority >= 0` → normal
- `priority < 0` → low
- 메모리 압박 시 low 일시 중단 → 시스템 안정

### CPU/Memory/Custom = Worker Thread 풀로 오프로딩
- 일반 작업은 메인 스레드, 무거운 작업은 Worker
- 타입별 동시성 cap (`WORKER_MAX_CPU_CONCURRENCY` 등)
- 워커 장애 시 자동 교체 (헬스체크)
- **이유**: 메인 이벤트 루프 블로킹 = 전체 throughput 붕괴

### 이벤트 기반(`setImmediate`) + 폴링 fallback
- 큐 처리는 이벤트 트리거 → 즉시 처리
- 폴링은 안전망 (이벤트 누락 대비)
- **재사용**: Node.js에서 큐 처리 표준 패턴

### 큐 포화 시 즉시 거부 (`QUEUE_OVERFLOW_THRESHOLD`)
- 메모리 무한 적재 방지
- fail-fast로 클라이언트가 빠르게 재시도/우회 결정
- **교훈**: 큐 무한 길이는 backpressure 무력화

### 큐 스냅샷 영속화 (옵션, file strategy)
- 프로세스 재시작 시 큐 복원
- file strategy 외에 추후 Redis/DB 추가 가능
- **이유**: 인메모리 큐는 재시작 시 손실. 옵션으로 안전성 추가

### Go Heavy Worker Engine 추가 (듀얼 엔진)
- NestJS만으론 진짜 CPU 집약 작업에 한계
- Go로 heavy worker 따로 구현 + NestJS와 연동 (commit `b180612`)
- **이유**: Node.js Worker Thread도 GC/이벤트 루프 한계. Go는 진짜 CPU bound 처리에 유리

### 부하 테스트 대시보드 (SSE 스트리밍)
- `/queue-stats` SSE → 실시간 큐 상태 시각화
- 부하 테스트 결과 즉시 관측
- **재사용**: SSE + 차트 = 가벼운 실시간 대시보드

### Docker 구성 + DB 드라이버 추상화
- 단일 명령으로 실행
- DB 드라이버 추상화 → 영속성 strategy 변경 쉬움

## 실패담 / 디자인 도전

### God File 분리 (queue.service.ts, worker-pool.service.ts)
- 인프라 코드도 갓 파일화
- **수정**: 큐 서비스/워커 풀 분리 (`c4f2ef4`, `b1bda51`, `9f39d8b`)
- **교훈**: 인프라 코드는 도메인 코드보다 더 god화 잘 됨 (책임 경계 모호)

### 알 수 없는 workloadType — 일반 큐 fallback + 카운트
- 분석 못한 workloadType이 있으면 무시 X → 일반 큐로 fallback
- `workloadGeneralQueueFallbackCount` 카운트 → 운영자가 인지
- **교훈**: silent fail 금지. fallback도 카운트해서 가시화

### WorkerTaskRouterService 테스트 추가 (`8699170`)
- 리팩토링 후 라우팅 로직 변경
- 테스트 없이 진행하면 회귀 잡기 어려움

## 기술 패턴 (재사용 가능)

### 우선순위 큐 + 메모리 압박 시 low 중단
- 시스템 안정성 패턴
- 메모리 임계 도달 → 가장 덜 중요한 작업부터 잘라냄

### Worker Thread 풀 + 타입별 동시성 cap
- CPU/Memory/Custom 각각 cap
- 한 타입 폭주가 다른 타입 영향 X

### setImmediate + 폴링 fallback
- 이벤트 누락 시 폴링이 안전망
- 즉시성 + 안정성 둘 다

### 큐 포화 즉시 거부 (overflow threshold)
- 무한 적재 방지
- backpressure 강제

### 스냅샷 영속화 + 복구
- 인메모리 큐 안전망
- file → Redis → DB strategy 교체 가능

### Node.js + Go 듀얼 엔진
- I/O는 Node.js, CPU bound는 Go
- HTTP/gRPC로 연결

### SSE 스트리밍 대시보드
- WebSocket 없이 실시간 관측
- 큐 상태 모니터링에 충분

### 운영 카운트로 silent fail 가시화
- fallback도 카운트 → 운영자 인지
